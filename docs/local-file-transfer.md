# 局域网文件传输（3118）

此功能为 Android standalone 版增加的独立实现。两端都需要安装支持该协议的怀旧版；原版 VoceChat、QuickPic、AirDrop、小米快传不能直接互传。

## 操作

1. 两台设备连接同一 Wi-Fi，打开“聊天页 + → 文件传输”；也可以从头像账户面板的 + 进入。
2. 聊天附件回形针打开原图片/视频面板，“文件”左侧是“快传”；已选相册项目会带入快传待发送区。
3. 发送端选择文件（最多16个），点击附近接收设备右侧的发送。
4. 两端核对本次六位校验码，接收端确认接收后开始传输。进度和结果在页面显示，可主动取消。
5. 接收成功后，从接收记录右侧下载按钮保存到手机。图片/视频沿用现有媒体保存逻辑，其他文件保存到 Download/vocechat。

自动发现不可用时，可在接收端复制连接信息，到发送端添加设备。连接信息含本次临时证书指纹，退出后重新打开页面需重新复制。路由器访客网络、客户端隔离、VPN路由或系统防火墙仍可能阻止直连。

## 行为与边界

- 文件直接在局域网设备间传输，不经过 VC 服务器，不产生普通聊天消息，不占用 VC 服务器附件空间。
- 目前只支持私有IPv4局域网。设备需要打开传输页面才能被发现和确认接收；切到后台停止广播发现，已接受的传输由独立前台服务继续。
- 离开传输页面会询问取消当前传输。切换账号取消任务；接收文件按当前账号隔离存放，不进入媒体缓存清理范围。
- 一次处理一项传输请求；确认等待60秒，上传空闲超时，失败或取消删除当前未完成文件。已完成的其他文件保留。
- 接收文件先写临时文件，大小和SHA256均通过才转为正式文件。同名文件改名，不覆盖已有文件。
- 普通文件流式读写，发送前流式计算SHA256，不把整个文件读入内存。文件选择器/Android内容提供方仍可能先复制文件到本机缓存，因此需要可用磁盘空间。
- 没有断点续传、跨公网中继、持续后台接收和聊天文件自动切换快传。普通服务器上传是另一条链路，其真实大文件失败问题仍未修复完成。
- 文件留存在应用存储，卸载/清除应用数据会删除尚未保存到手机的接收文件。

## 协议

新编写的 `vocechat-lan-1`，没有复制QuickPic闭源核心代码，也不兼容其旧协议。

- UDP53318，组播239.77.18.1并补发本地接口广播，每2秒一次，8秒移除离线设备；最多64个发现记录，数据报限制4096字节。
- 发现记录只包含协议、设备别名、临时证书SHA256指纹、TLS端口；使用数据包来源地址，拒绝公网IPv4。
- Android原生生成临时RSA2048证书，密钥只在内存；HTTPS服务绑定随机端口。客户端使用不含系统受信根的证书上下文，并固定所选设备证书指纹。
- POST /v1/offer：随机会话ID、256位随机会话令牌及文件元数据；JSON限制64KiB。接收端显式确认后才接受上传。
- 六位人工校验码由两端证书指纹及本次TLS保护的会话令牌派生，不能仅通过重复公开发现记录复用相同校验码；用户应核对后再接受。
- PUT /v1/file/{session}/{file}：Bearer会话令牌、精确Content-Length、流式文件体；不使用VC令牌。
- POST /v1/complete/{session} 和 /v1/cancel/{session} 使用同一会话令牌。
- 本地网络发现本身不认证设备名称，六位校验码也不替代可信接收人的人工确认。没有后台扫描或自动接受任意文件。

## 验证

全客户端回归、Android原生证书/签名验证和局域网协议测试分别运行。协议测试包含150MiB合成文件、空文件、拒绝、错误指纹、取消、部分文件清理、路径处理、重复文件名、校验失败和UDP发现。实机结果须单独记录，不能用本机测试代替两台手机的验证。

可选真机测试端为 `tool/device_lan_peer_test.dart`，不会随普通 `flutter test` 运行。显式设置 `VC_LAN_TEST_DIR`（测试输出目录）、`VC_LAN_TEST_PHONE`（目标手机私有IPv4）、`VC_LAN_TEST_BROADCAST`（同子网广播地址）后执行：

    flutter test --no-pub --reporter expanded tool/device_lan_peer_test.dart

电脑端生成150MiB+17字节合成文件及临时证书，只自动接受该文件大小和SHA256完全一致的回传；通过测试目录的command文件传入send/cancel/stop。send只向显式指定IP的已发现手机发送，手机仍需人工接受。退出后销毁临时证书；合成测试文件在指定目录保留，便于核对和清理。不读取或上传真实聊天附件。

## 2026-10-29 真机记录

已在连接的 Xiaomi Android16 手机上保留数据覆盖安装3118，与同一Wi-Fi中的电脑测试端完成：

- 双向自动发现：电脑发现手机，手机页面出现Codex测试设备。
- 接收请求显示发送方、150MB文件及六位校验码；首次等待超时未写文件，重发后用户确认接收。
- 电脑→手机完成157,286,417字节文件传输；用户将接收文件保存到手机下载目录。
- 手机→电脑从系统文件选择器选取同一下载文件后回传成功。
- 原始合成文件、手机导出文件和电脑收到的回传文件SHA256均为`4244becf274f9f08f1a0bdb7962c0619be82e58c558c138b20044ce5ef26323f`。
- 回传期间9次PSS采样为184,401–204,913KiB（约180.1–200.1MiB），未闪退。
- 传输中出现独立local_file_transfers/dataSync前台服务；完成后该服务退出，原后台消息连接服务仍在。

本轮验证为一台真实Android手机与电脑同协议测试端，尚未单独进行两台Android手机互传、锁屏/退后台持续传输及断网后恢复的真机测试。取消与部分文件清理已有自动测试。临时电脑测试端在测试后停止，未发送真实VC聊天消息或改动消息通知偏好。
