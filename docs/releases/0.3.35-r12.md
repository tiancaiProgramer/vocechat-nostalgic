# 0.3.35-r12（3133，本地验证版）

修复后台消息模式在手机重启及进程被系统回收后缺少恢复入口的问题。

- 注册开机完成和应用更新后的恢复接收器；仅在用户已解锁、开启后台消息模式且已有登录会话时请求恢复。
- 后台服务改为系统可恢复的sticky服务，能处理系统传入的空启动指令；先建立前台服务，再重新建立Flutter消息运行环境。
- 冷启动和后续打开界面复用同一个引擎，不创建第二个登录；消息分发及连接监听独立于聊天页面挂载。
- 开机恢复不启动麦克风或恢复旧通话；退出登录、关闭后台消息模式或切换FCM模式后不自动恢复后台服务。
- 新版第一次正常打开后保存恢复所需的会话标识，不保存额外明文登录凭据。

验证：35项后台、重连和启动相关Flutter测试通过、2项渠道条件用例跳过；26项Android通知、启动策略、空指令重建及引擎所有权测试通过；main.dart静态检查无问题。原签名ARM64包及16KiB ZIP对齐检查通过，已保留数据覆盖安装到手机，正常打开后前台服务运行。

真实开机验证：用户重启并解锁、未打开怀旧版。设备运行时长约95秒，日志确认由BOOT_COMPLETED启动后台服务、创建后台Dart引擎，前台服务类型仅specialUse，并已建立至VC服务器的连接。没有手动打开应用。锁屏收消息和长时间待机仍待验证。

Android的系统强行停止会阻止应用自动恢复，之后需手动打开；本修复不绕过该用户操作。厂商后台管理和长时间待机行为仍需实机观察。

本版本未提交或发布GitHub。

后续锁屏验证失败：用户未收到通知，对端显示离线。此前仅确认开机服务启动与TCP存在，不能作为消息会话恢复证据。r13已补充无界面帧下的状态调度修复与有效事件诊断。
